## 2026-08-05 - SQLite Range Checks and Composite Indexes for High Performance Rate-Limiting and History Queries
**Learning:** In SQLite, wrapping a column in a function (such as `date(created_at)`) within a `WHERE` clause prevents SQLite from using standard column indexes for filtering. This leads to costly full-table or full-index scans. By refactoring the filter to a range-based comparison (such as `created_at >= date('now')`), SQLite can perform efficient index range scans. Additionally, composite indexes (e.g., `(user_id, created_at)`) allow SQLite to simultaneously filter by user ID and fetch rows in sorted order of creation date in `O(log N)` time, completely eliminating expensive filesort operations for history retrieval.
**Action:** When designing and optimizing SQLite database queries, avoid wrapping column names in SQL functions in `WHERE` clauses. Refactor them into range-based checks against direct column values and define multi-column composite indexes that match the query's filtering, sorting, and range-scanning requirements in order.
