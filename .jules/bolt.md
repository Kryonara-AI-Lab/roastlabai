## 2026-08-12 - [SQLite Range Index Seek via Sargable Expressions]
**Learning:** In SQLite, applying functions to columns in a WHERE clause (such as `date(created_at) = date('now')`) makes the expression non-sargable, forcing a full-table scan or a full-index scan because the index cannot be traversed efficiently. Changing this to a range-based comparison (such as `created_at >= date('now')`) preserves semantic correctness (since SQLite stores datetime values as comparable ISO 8601 strings) while allowing the query planner to execute a high-performance covering index range seek and avoid temp B-tree filesorts entirely.
**Action:** Always write range-based, function-free query filters (`column >= boundary`) instead of function wrappers on columns when querying indexed fields in SQLite.
