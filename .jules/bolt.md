## 2026-02-09 - SQLite Composite Indexing and Range Query Optimization
**Learning:** Applying functions like `date(created_at)` on SQLite database columns prevents the query planner from utilizing regular indexes, causing slow O(N) full table scans. By restructuring queries to use index-friendly range-based checks (e.g., `created_at >= date('now')`) and introducing composite indexes (like `(user_id, created_at)` and `(ip_address, user_id, created_at)`), we can convert O(N) full table scans into extremely fast O(log N) covering index searches. Additionally, composite indexes that align with `ORDER BY` columns allow SQLite to completely skip temporary in-memory B-Tree sorting.
**Action:** Always avoid function transformations on columns in `WHERE` clauses. Instead, formulate query filters as range comparisons and create covering composite indexes tailored to the query's filter and ordering criteria.
