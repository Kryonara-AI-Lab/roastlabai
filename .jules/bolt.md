## 2026-08-01 - [Flask DB Connection Caching & Indexing]
**Learning:** Found that the Flask application was opening and closing independent SQLite database connections up to three times per request in a single execution flow (first checking rate limits, second saving the verdict, third loading user history). In addition, the `roasts` table did not have any composite indexes, leading to full-table scans when filtering on `user_id` or `ip_address` combined with datetime order.
**Action:** Use Flask's request-scoped `g` context to cache the SQLite database connection, ensuring only one connection is opened per request. Register `@bp.teardown_app_request` to cleanly teardown the connection. Add composite database indexes on `roasts(user_id, created_at DESC)` and `roasts(ip_address, user_id, created_at DESC)` to allow instant O(log N) operations.
