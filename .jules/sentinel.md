## 2026-07-13 - Secure Session Cookie & Response Security Headers
**Vulnerability:** Hardcoded Flask secret key (`'roastlab_secret_key_change_this_immediately'`) and missing standard security response headers (such as `X-Frame-Options`, `X-Content-Type-Options`, and `Referrer-Policy`), risking session hijacking, clickjacking, and MIME type sniffing attacks.
**Learning:** Hardcoded Flask secret keys make session signing predictable, allowing session spoofing if the key is leaked or guessed. Lacking secure defaults on session cookies (such as HttpOnly, SameSite) and lacking security-related HTTP headers leaves users vulnerable to various web-based attack vectors.
**Prevention:** Dynamic fallback generation of secret keys via `secrets.token_hex(32)` if no environment-defined variable is found, combined with strict default secure cookie options (`SESSION_COOKIE_HTTPONLY=True`, `SESSION_COOKIE_SAMESITE='Lax'`) and global `@bp.after_request` headers injected on every response.
